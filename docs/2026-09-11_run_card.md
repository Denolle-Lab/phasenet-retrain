# Run card and rejection-ledger gate (46A tooling)

*2026-09-11, branch `issue/46a-run-card` stacked on `issue/41a-label-policy`
(PR #66) at `b712541`. Tooling for checkpoint 46A of issue #46; the gate is
the answer to the silent-failure defect of issue #34 (a failed read used to
become a zero waveform with a noise label, and nothing recorded it).*

Requirement (training strategy): every run writes `results/<run>/run_card.json`
before the first optimiser step and again at the end. A run without a
complete card is not a result.

## Files

| File | Role |
|---|---|
| `scripts/run_card.py` | card assembly, ledger gate, `check`/`show` CLI; pure Python + numpy/pandas/yaml, no torch |
| `scripts/finetune.py` | wiring in `train()`: gate after `build_dataloaders`, card before the loop, `finalize_run_card` at the end; `--allow-rejections` flag |
| `tests/test_run_card.py` | 15 tests on synthetic manifests and ledgers in temp dirs |

## Card fields

`build_run_card(config, config_path, manifest_paths, rows_read=None, extra=None)`
returns the start-of-run card; `write_run_card(card, results_dir)` writes
`results_dir/run_card.json`.

| Field | Content | Source |
|---|---|---|
| `card_version`, `status`, `run_name`, `started_utc` | `46a-v1`; `started` then `finished`; `logging.run_name`; UTC | |
| `config.file_sha256` | sha256 of the YAML bytes | `config_path` |
| `config.canonical_json_sha256` | sha256 of the parsed config as sorted, whitespace-free JSON (layout-independent) | `config` |
| `config.seed`, `seed_source` | `seed` key, or the `finetune.py` default 42 when absent | |
| `config.label_policy`, `config.augmentation`, `config.window_length` | `data.*` sections verbatim (null when absent) | |
| `config.training`, `config.model` | optimiser, loss, scheduler, early-stopping, distillation keys; `model` section | |
| `loader_contract_version` | `waveform_contract.CONTRACT_VERSION` (`34a-v1`) | |
| `arrival_schema_version` | `arrivals.SCHEMA_VERSION` (`41a-v1`) | |
| `manifests.<split>.file_sha256` | sha256 of the CSV bytes | |
| `manifests.<split>.keys_sha256` | order-independent hash of sorted (dataset_name, trace_name, chunk), the same function as `scripts/hash_manifests.py`, so it is comparable with `data/manifest_checksums.csv` | |
| `manifests.<split>.n_rows`, `rows_by_dataset`, `columns` | row count, per-source counts, column list | |
| `manifests.<split>.composition` | see below | |
| `exclusion_bundle` | sha256 of `data/exclusions/bundle.json`; until 33A releases one: `sha256: null`, `reason: "no bundle; 33A"` | |
| `ledger` | see the gate | |
| `versions` | python, platform, numpy, scipy, pandas; torch, seisbench, obspy, h5py when importable, else null | |
| `git.commit`, `git.branch`, `git.dirty` | `git rev-parse HEAD`; dirty = tracked files modified (untracked files ignored) | |
| `extra` | whatever the caller passes; `finetune.py` records `allow_rejections`, `resume_path`, `init_from`, `device`, `amp`, `n_supervised_samples` per split and the loader's label policy name | |
| `finished_utc`, `best_epoch`, `dev_metric`, `checkpoint` | null until `finalize_run_card` | |

Splits are whatever keys `manifest_paths` carries. `finetune.py` passes
`train` and `val`, plus `dev` when the config sets `data.dev_manifest`. No
config on this branch has a development excerpt yet; the card therefore
records train and val, and `check` requires only those two.

### Composition (per manifest)

Computed from the columns that exist; an absent column gives null and a
`*_reason` entry, never a guess.

| Key | Definition |
|---|---|
| `by_source` | `dataset_name` counts; `n_noise_rows` counts the explicit pools `noise_global`, `noise_prephase` |
| `by_distance_bin` | counts of `distance_bin` (else `dist_bin`) |
| `by_snr_bin` | counts of `snr_bin` if present; else `snr_db` (or `trace_snr_db`, `snr`) binned at the edges of `scripts/audit_generalization_hypotheses.py` (0, 5, 10, 20 dB), recorded as `snr_bin_edges_db`; the training manifests of `build_training_dataset.py` carry neither column, so this is null for them |
| `s_label_fraction` | rows with an S label over all rows; `s_label_fraction_signal` over non-noise rows. A row with `arrivals_json` has an S when the list has one (the loader lets the list override the legacy columns); other rows use `s_arrival_sample` |
| `multi_event_fraction` | rows whose `arrivals_json` lists more than one distinct `event_id`, or more than one arrival of the same phase; null with a reason when the column is absent (every manifest before 40A) |
| `arrival_tier_counts` | provenance tier counts over all listed arrivals |
| `negative_support` | counts of the `negative_support` column |
| `n_p_labelled_rows`, `n_s_labelled_rows`, `n_s_only_rows` | from the legacy columns (and the list for S) |

The composition is what the manifest requests. It is the achieved
composition only when the gate passes: zero rejected rows and the loader
served exactly the manifest's rows.

## The gate

The 34A loader appends one JSON record per failed row to
`<manifest stem>.rejected.<pid>.jsonl` beside the manifest and raises on the
first failure. The failure budget is zero
(`docs/2026-09-10_34a_loader_contract.md`).

- `verify_ledger(manifest_paths)` lists every `<stem>.rejected.*.jsonl` (and
  a bare `<stem>.rejected.jsonl`) beside each manifest and raises
  `RuntimeError` naming the split, file and the first 20 records when any
  record exists. A line that is not JSON counts as a record.
- `ledger_summary` (inside the card under `ledger`) records the files, their
  record counts and modification times, and `rows_read` per split against the
  manifest row count. `ledger_gate_passed` is true only when every count is 0
  and every split in `rows_read` matches.
- `check_run_card(path)` treats `ledger_gate_passed != true` as a failure, so
  a run started with `--allow-rejections` never passes `check`.

Ledger files accumulate across processes. After a rejection is inspected and
repaired, move the ledger files out of the manifest directory; otherwise the
next run is refused for the same records. That is intended: the ledger is the
record that a manifest was not clean, and clearing it is a deliberate act.

`finetune.py` order inside `train()`:

1. `build_dataloaders` (the preload itself raises on the first rejected row).
2. `verify_ledger` on the train and val manifests; abort unless
   `--allow-rejections`, which prints a warning and is recorded in
   `extra.allow_rejections`.
3. `build_run_card` with `rows_read = len(loader.dataset)` per split;
   `write_run_card` into `results/<run_name>/run_card.json`. This happens
   before the model is built, so before any optimiser step.
4. Training loop unchanged, except that the epoch of each `best.pt` and its
   validation metrics are kept.
5. `finalize_run_card(card_path, best_epoch, dev_metric, best_path)` adds
   `finished_utc`, `best_epoch`, `dev_metric` (`monitor` = the early-stopping
   monitor, plus every `val_*` metric of that epoch) and
   `checkpoint.{path, sha256, size_bytes}`. When no epoch improved in this
   process (a resume at or past `max_epochs`), `best_epoch` is null with a
   reason and `check` fails; a missing checkpoint is recorded, not fatal.

## Commands

```bash
python scripts/run_card.py check results/<run_name>/run_card.json   # exit 0 complete, exit 2 with the missing fields listed
python scripts/run_card.py check --start-only results/<run_name>/run_card.json   # during a run
python scripts/run_card.py show results/<run_name>/run_card.json    # summary; --json for the raw card
python -m pytest tests/test_run_card.py -q
```

`check` requires, non-null: the config hashes and seed, both contract
versions, `manifests.train` and `manifests.val` hashes, rows, per-source
counts and composition, `exclusion_bundle`, the ledger section with
`ledger_gate_passed` true, versions of python, numpy, scipy, pandas, torch and
seisbench, `git.commit` and `git.dirty`, and at the end `finished_utc`,
`best_epoch`, `dev_metric` and `checkpoint.sha256`. `config.label_policy` and
`config.augmentation` must exist as keys but may be null (a legacy config).

## Validation on 2026-09-11

Base `python` 3.9.20 with numpy 2.0.2, pandas 2.3.2, scipy 1.13.1, pytest
8.4.2; no torch, SeisBench or h5py:

```bash
python -m pytest tests -q               # 60 passed, 1 skipped (test_manifest_dataset needs torch)
python -m py_compile scripts/finetune.py
```

The `finetune.py` wiring was compiled, not executed, on this laptop: the
script imports torch and SeisBench at module level. A card built here shows
`versions.torch` and `versions.seisbench` null and fails `check` on exactly
those two fields, which is the intended reading of "not a training result".
The first server run of a 46A arm (`configs/e0_46a_*_targets.yaml`) exercises
the wiring; check its card with the `check` command before reporting anything
from it. Until 33A releases `data/exclusions/bundle.json`, every card carries
`exclusion_bundle.sha256 = null` with the reason `no bundle; 33A`.
