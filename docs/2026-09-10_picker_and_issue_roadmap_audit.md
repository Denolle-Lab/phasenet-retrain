# PhaseNet retraining and issues #33–#50: independent audit

2026-09-10 · Branch `audit/2026-09-07-generalization` · HEAD `7763236`.

**Decision: keep `jma_wc` as the deployment reference; repair the measurement and training contracts before starting #45.** The roadmap moves toward the right data—continuous aftershocks, swarms, volcanic unrest and realistic noise—but currently contains defects and conflicting acceptance rules that could reproduce the previous selection failure at greater expense.

The evidence supports a combination of unsuitable model selection and altered supervision, with important implementation errors still present. It does **not** establish that 527k windows are intrinsically insufficient, that temperature 4 caused the loss, or that every observed deployment deficit is irreversible forgetting. Those are hypotheses requiring controlled comparisons.

This audit read the live GitHub issues, source and history, stored benchmark results, local v7 checkpoint, cached parent/deployment weights, and held-out reference metadata. All 18 issues were OPEN without comments when read; their bodies and timestamps are preserved in [the issue snapshot](audit_2026-09-10/issues_33_50.json). It also inspected the two local QuakeScope notebooks and conversion script. No server training manifests, other fine-tune checkpoints, or epoch histories were available. The pre-existing edit to the surface-event plan was preserved. No GitHub issues or production code were changed.

## Findings that should block new training or model selection

**1. Native-rate waveforms and labels lose alignment during training. Confirmed code defect; contribution to historical v7 remains unquantified.**

`build_training_dataset.py:568–578` writes arrival indices from source metadata without a sample-rate field or conversion. `ManifestDataset.__getitem__` resamples the waveform at lines 398–399, then uses the original P/S indices at lines 414–415. The indices must undergo the same time-coordinate transformation.

An offline probe of the actual loader placed a smooth pulse at 4 s in a 60 s native-rate waveform. The resampled pulse is at sample 400; the labels are:

| Native sampling rate | Label sample after loading | Timing error |
|---|---:|---:|
| 20 Hz | 80 | −3.20 s |
| 40 Hz | 160 | −2.40 s |
| 50 Hz | 200 | −2.00 s |
| 100 Hz | 400 | 0.00 s |

This is much larger than the 0.1 s Gaussian width and 0.5 s matching tolerance. The bug also exists in commit `3bf98c4`, which introduced the v5–v13-era files, so it is not a new audit-branch regression. The installed SeisBench LenDB converter explicitly uses 20 Hz and an **estimated**, fixed sample-80 P arrival; LenDB is an enabled training source. This identifies a credible affected source, but the server's actual cached metadata and v7 manifest must establish the number of affected rows. Do not infer their count from source caps.

The direct HDF5 readers additionally assume 100 Hz (`manifest_dataset.py:343–350`), and shape repair does not establish physical component order (`:210–224`). Audit actual HDF5 `data_format`, native/effective sample rates, `ZNE` versus other component orders, units and trace start times per source. Assert alignment using absolute pick times or explicit original indices and rate ratios. Required fixtures: 20/40/50/100 Hz, missing channels, S-only traces, offsets near crop boundaries, and waveform-fetch failures. Owner issues: #34, #40, #43; this work precedes #45.

**2. The threshold sweep is not equivalent to production picking at each threshold. Confirmed defect in this branch and both QuakeScope notebooks.**

`heldout_testset_score.py:133` calls `classify` once at 0.02. Lines 60–61 and 140–146 subsequently remove low-scoring picks. SeisBench extracts picks using on/off thresholds, with the off threshold half the on threshold. A low threshold can connect two peaks into one trigger and retain only its maximum. Raising the threshold can split that trigger into two picks; filtering the original pick list cannot recover the second one. This follows both the installed source and the [SeisBench PhaseNet implementation](https://seisbench.readthedocs.io/en/latest/_modules/seisbench/models/phasenet.html).

Reproduction: two peaks, 0.8 and 0.7, connected by probability 0.03 give **one** pick when extracted at 0.02 and filtered at 0.3, but **two** when extracted directly at 0.3. This directly concerns dense aftershocks and elevated coda backgrounds. Both `phasenet_global_sequences.ipynb` and `phasenet_sequence_comparison.ipynb` contain the same approach, so previously reported matched-budget losses need corrected extraction. The direction and magnitude of the model-comparison bias are unknown.

A deterministic ten-minute development excerpt, Adriatic station IV.AOI, did **not** exhibit the discrepancy: both methods produced parent P/S counts 7/7 and v7 counts 7/3. This is a useful limit on the finding: the defect is reproducible, but not every stream activates it, and these emitted counts alone are not recall or false-positive measurements.

Fix #35 by storing continuous probability annotations once, then applying the actual pick extractor at **each** threshold. Match labels, time grids and valid support explicitly for ensembles. Persist pick IDs, phase, network/station/location, score, time, model hash, threshold and matching assignments. #36 needs that pick store; the current scorer only returns aggregate rows and discards it.

**3. The scorer has additional problems specifically relevant to multiple events. Confirmed.**

`reference_from` collapses arrivals from different events within 0.5 s (`heldout_testset_score.py:43–56`), erasing precisely the close arrivals the new corpus is intended to recover. Deduplicate duplicate bulletin representations using event/station/phase identity, rather than treating temporal proximity as duplicate identity. Define separately which phase branches should count as distinct targets.

The nearest-first greedy matcher (`:64–78`) can undercount valid one-to-one matches. With references `[0.0, 0.6]`, candidates `[-0.4, 0.1]` and tolerance 0.5, it finds one match although two are feasible. Require maximum-cardinality matching, with minimum residual as a secondary objective, on sorted arrivals. Preserve event IDs and test overlapping events, duplicate agency picks and exact tolerance boundaries.

`matched_budget` mixes multiple windows of the same sequence before interpolation (`:81–97`), instead of either conditioning on window or first aggregating counts by model/phase/threshold. Main also never calls this helper, so #35's advertised command does not produce the required matched-budget table. The 0.3 threshold is included twice, duplicating rows (`:37,140,152`). Linear interpolation across a coarse sweep is not an attained operating point; after fixing extraction, event counts may not be monotonic in threshold. Report actual operating points and a predefined budget rule.

Inference failures are printed and skipped (`:134–135`) without a structured failure table or validity gate. Partial waveform coverage is not propagated to the reference denominator. Require common valid waveform support across compared models, plus separate operational failure rates. Do not quietly exclude difficult station-days from the claim of deployment performance.

**4. Missing labels become explicit negative training targets. Confirmed behavior; a strong candidate for S and aftershock degradation.**

`make_labels` assigns P/S/N from at most one P and one S; absent S gives zero S and noise=1 away from the P (`manifest_dataset.py:258–266`). The builder disables S for selected sources and every teleseismic row (`build_training_dataset.py:563–566`), requires P for all ordinary signal rows (`:422–425`), and the loader treats missing P as an all-noise window, even if S exists (`manifest_dataset.py:401–412`).

The mechanism is stronger than “too few S examples.” At an unlabelled physical S arrival, cross-entropy actively pushes the S logit down. An unlabelled second earthquake is similarly trained as noise. Distillation then fights the supplied label on some of those samples. Longer windows increase exposure to incomplete catalogues unless label completeness is addressed.

The documented 38% S fraction is measured before cropping. P is usually placed around sample 900, leaving about 21 s after P in a 30 s window; S outside that window is discarded (`:419–420`). Therefore #34 must report **effective P/S supervision after resampling and cropping**, not merely non-null manifest columns: by distance, source, rate, SNR, phase quality, S–P time and window position. Quantify physical arrivals with unknown labels separately from confident negatives. Include S-only crops as normal signal examples.

For #40/#43, use arrival lists and explicit label-validity masks or a partial-label loss. A missing bulletin pick is not proof of no phase. Annotate all known events reaching the station, including origins outside the local harvest box or before the window. Retain reviewed negative intervals. For multi-arrival soft targets, define how overlapping P/S Gaussians are combined: the current `N=1-max(P,S)` can give channel sums above one (2.0 for coincident peaks), so it cannot be carried unchanged into superposition with categorical soft cross-entropy.

**5. “Built” does not mean a sequence can support the planned acceptance test. Confirmed reference-coverage gaps.**

The following is a join of committed reference picks to stations marked fetched and the frozen windows, with the scorer's current duplicate rule. These are availability counts, not newly measured model performance. They are upper bounds on usable references because common component coverage and waveform gaps are not yet masked. Full results: [reference_coverage.csv](audit_2026-09-10/reference_coverage.csv).

| Sequence | Accepted references in the full pick file | P / S on fetched stations in scoring windows | Limitation |
|---|---:|---:|---|
| Noto swarm 2023 | 9,890 | **0 / 0** | No reference/waveform overlap; cannot score recall |
| Noto 2024 | 13,719 | 100 / 81 | Two fetched stations; restricted-network coverage missing |
| Hualien 2024 | 30,876 | 86 / 63 | One fetched station; cannot validate local multi-station association |
| Fagradalsfjall 2021 | 3,911 | 16 / 8 | Only two explicitly manual P picks and zero manual S before deduplication |
| Campi Flegrei 2023 | 95 | 30 / 26 | References represent only five events on fetched stations |
| Petrinja 2020 | 4,019 | 152 / 142 | Zero explicitly manual rows in this usable subset |
| La Palma 2021 | 3,151 | 940 / 951 | Zero explicitly manual rows; accepted ISC unknown-mode references |
| West Bohemia 2018 | 9,769 | 137 / 157 | Sparse overlap despite a much larger catalogue |

Unknown ISC mode is not evidence that a pick is wrong. It is also not verification of manual provenance. Preserve separate reviewed-manual, reviewed-bulletin/unknown-mode, automatic and unverified tiers, with sensitivity analyses. The parent missing a reference is a review trigger, not proof of a bad reference.

The builder picks the six stations with the most references, accepts streams based on only the first trace's length, fills gaps with zeros, and resolves ambiguous station codes alphabetically (`build_heldout_testset.py:624–674`). Fix location/channel/epoch identity using inventory and coordinates; reject unresolved ambiguity. Audit waveform availability by component and station-window, retain gap masks and compute actual valid station-hours. File checksums verify identity, not scientific adequacy.

Current mainshock windows start 600 s after the mainshock and last 2–3 hours; swarms use two busy 3-hour windows. They are useful stress-test excerpts but cannot substantiate the plan's first-48-hour recovery or weeks-long migration claims. Add the excluded first ten minutes, later hour/day blocks, ordinary and quiet days, and stations chosen independently of analyst-pick density. Treat clipping/saturation and telemetry loss near the mainshock as measured operating conditions. #37 is consequently a dependency of the relevant #35/#36/#49 gates, not merely optional data enrichment.

## What most likely happened to JMA_WC

**The established selection failure.** The legacy benchmark finds a peak inside ±5 s of the known arrival (`eval_finetuned.py:157–172`), then assesses its probability; it never asks whether the deployed picker would emit that arrival amid other triggers. It has no representative continuous negative-time denominator. Timing on detected picks rewards a model that drops difficult onsets; even timing on all oracle-search peaks is not an operational objective. Repeatedly selecting among v1–v20 on that benchmark further consumed its independence.

The stored paired audit—not a new inference run—gives the following at threshold 0.3:

| Same-trace benchmark comparison | Parent | v7 | Difference |
|---|---:|---:|---:|
| P recall, all distances | 0.884 | 0.854 | −3.0 percentage points |
| S recall, all distances | 0.549 | 0.505 | −4.4 points |
| Regional S recall | 0.358 | 0.285 | −7.3 points |
| P MAE, picks both detect | 0.214 s | 0.195 s | 19 ms better |

Source: [paired benchmark table](audit_2026-09-07/task2b_paired_full_benchmark.md). Its trace-bootstrap intervals do not account for shared events or stations. The clean-holdout aggregates use different populations for parent and v7 and must not be described as a paired comparison.

**The plausible training mechanism.** Heterogeneous/incomplete P/S labels, incorrect native-rate alignment, fixed crops, deterministic cached windows and weak deployment-oriented augmentation can move the student toward a narrower task. The low-SNR P and regional S pattern in the stored tables is compatible with this mechanism. The small real-data probe also confirms the parent and student behave differently after a verified export, although its counts do not establish which picks are correct.

**Calibration contributes, but its causal explanation is not established.** The stored probability distributions show a downward shift and the rank-remapping audit reduces many deficits. However, rank-mapping onto the parent's marginal distribution on the same positives is neither held-out calibration nor evidence of improvement at a true false-alarm budget. `AUC_recall = mean(probability)` is sensitive to monotone probability transformations and is not ROC-AUC or average precision. It should not be treated as calibration-independent discrimination.

The KL implementation uses softened logits and T² scaling in the usual direction, teacher to student (`fine_tune_model.py:264–276`). A high temperature alone does not prove why the student's T=1 confidence decreases. Hard-label CE differs from the parent's soft labels, but changing it alone already failed to establish an improvement. Diagnose these terms with loss-component and gradient-scale logging on correct labels, not another broad recipe change.

**Batch normalization deserves a cheap ablation.** The v7 checkpoint has altered running statistics; for its input BN the median running-variance ratio to the parent is 0.758. Statistics adapt during training independently of a tiny parameter learning rate. Freezing parameter gradients alone does not freeze BN statistics. Compare frozen parent BN versus adaptive BN, with affine parameters controlled separately, on development data. Replacing buffers post hoc is a diagnostic, not an accepted model. The teacher in the saved checkpoint is exactly the cached parent, so teacher drift is not supported for this artifact.

**What the checkpoint checks ruled out locally.** The epoch-44 checkpoint contains 111 student and 111 teacher tensors. Every student tensor equals the cached `quakescope2026` export; every teacher tensor equals the cached `jma_wc` parent. Student loading succeeds strictly under `ZNE`, `PSN`, std normalization and filter factor 2. There is no evidence here of exporting the teacher, wrong network width, or swapped phase channels. This does not certify the actual server/container image; pin its file hashes and dependency versions in #49. The training loader clips normalized amplitudes at ±10 whereas ordinary SeisBench inference does not; align and test this preprocessing distinction for impulsive signals.

**What remains unproved.** The historical incidence of bad rate alignment, missing-label negatives, failed HDF5 reads and source overlap needs the server. Fetch exceptions still turn into permanent cached zero/noise examples (`manifest_dataset.py:379–395`); logging them does not bound the contamination. Require a rejected-row ledger and stop on systemic failures. Epoch losses are unavailable, so claims about overfitting or optimization collapse rely on config commentary. The existing position-bin audit did not find a v7 P-position trend; fixed cropping is a recipe defect, not an established explanation of v7's P deficit.

The [JMA parent study](https://link.springer.com/article/10.1186/s40623-024-02091-8) used 6.1 million waveforms, selected reliable P/S pairs, randomized P position and used soft Gaussian labels. That motivates preserving supervision quality; it does not establish a minimum fine-tuning dataset size. Its inclusion of low-frequency earthquakes also matters when deciding what the new noise corpus should suppress.

## Revised experiment order and decision rules

**Gate A: make the failure reproducible.** Complete #33 and the expanded #34; fix #35's scoring mechanics; move #44 forward. Record a model contract (sample rate, component/phase order, normalization, width, input length, annotation overlap/blinding, trigger rule and checkpoint hash). Verify parent→wrapper→export probability parity before any optimization. Use existing known failures as regression cases and define a genuinely unexamined acceptance panel.

**Gate B: establish credible continuous baselines.** Complete the evaluability parts of #37, then #35/#38/#36 on development/regression data. Compare parent, v7, available v11, instance and specified ensembles. Account for the INSTANCE parent's possible Italian training overlap when interpreting Norcia; fine-tune exclusions cannot remove information already in a pretrained model. Give every baseline a training-domain/parent-provenance label. Distinguish catalogue-relative recall from true event completeness.

**Gate C: diagnose with a small corpus.** Implement #39–#43 on a pilot containing inspected examples at every native rate and S-label condition. Run controlled comparisons: faithful parent-initialized soft-label fine-tune; then incomplete-label handling, BN freeze/adaptation, distillation/replay, and real-noise augmentation. Log per-term losses, gradient norms, effective positive-label counts, rejected records, sampling composition and continuous validation curves. Use multiple seeds for comparisons that guide the full campaign. Prefer a few interpretable runs to many simultaneous recipe changes.

**Gate D: scale the recipe that passes.** Run #45 with nested event groups at fixed composition, followed by the remaining #46–#48 experiments. Include validation/model-selection compute in the budget. The existing RAM cache stores waveforms and dense labels: at 4M × 6000 samples × 3 channels × float32 × 2 arrays, training alone requires **576 GB decimal**, before validation/test arrays, loader copies or augmentation context. `manifest_data_module.py` eagerly loads all three splits, even when training only uses two. Use disk-backed shards/memory mapping, worker-local readers and labels generated per batch; benchmark throughput instead of assuming linear eightfold scaling from v7.

**Gate E: acceptance and deployment.** #49 operates on an eligible sealed panel with frozen thresholds and associator. Predefine practical margins from campaign needs and available event/day counts. Bootstrap paired event/station-day blocks, retaining both phases together; six P/S pairs from three sequences are not six independent trials. Include multiple regimes and station classes, not only a European development panel. Report degradation limits separately for S, weak P, close arrivals, noisy days and missing-channel conditions. Run #50 as a separate pilot whose geographical handoff is tested with the main picker.

For every gate, report (1) P/S recall within phase-appropriate tolerance at a fixed independently calibrated nuisance-pick budget, (2) actual emitted workload per valid station-hour/day, (3) timing residual distributions including tails and misses, and (4) event-level recovery and split/merge/unmatched outcomes with fixed association settings. Manual or blinded review is needed to turn unmatched predictions into false-positive claims. Neither catalogue absence nor model disagreement is ground truth.
